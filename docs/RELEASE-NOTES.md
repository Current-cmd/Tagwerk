# Release notes, 2026-11-21

`main` now contains the full Tagwerk build (previously the skeleton only).

## What is in it
- Pipeline on the GPU laptop: upload -> ffmpeg -> Whisper int8 -> ArUco + YOLO11s + YOLO-World + RelateAnything (GPU)
  -> weather -> structuring (Claude when `ANTHROPIC_API_KEY` is set, else German/Dutch/English rules) -> project
  state (element states only go up; voice/note confirms, vision proposes) -> Neo4j -> websocket.
- Progress loop: BoQ-weighted activity %, earned value, day-by-day forecast with crew absences (3 working days per
  sick report), finish-to-start and start-to-start successors.
- Pages: live graph (6 columns for small projects, aggregated for large ones), Bauleiter dashboard, site-manager
  view, upload, scan. Exports: P6 XML (baseline/progress, FS+SS links), GAEB X83/X84, Outlook .ics.
- Projects: `hoersaal` (demo seed, 32 elements), `schependomlaan` (open BIM dataset import: 2,082 elements,
  100 real tasks, 6 storeys), and projects generated by scan mode from a video (vision detections + building terms in
  the speech).
- Replay of any processed capture from its cached stage outputs (no GPU, no Claude, no weather call).

## Known limitations
- Schependomlaan has no as-built data: its weekly Synchro snapshots are planned states (a task's elements appear when
  it starts), so started tasks read 100 % and SPI is inflated.
- Vision recall on large surfaces (walls, scaffolding) is weak and there are false positives; vision therefore only
  proposes.
- The rules cannot resolve pronouns ("das ist der Endzustand"); the Claude path would, but is only tested with a fake
  client (no API key).
- The auditorium seed is a placeholder until real measurements, photos and markers exist; the P6 XML was not imported
  into a real Primavera.
